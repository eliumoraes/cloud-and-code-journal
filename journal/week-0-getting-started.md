## 📚 Sistema de Revisão Espaciada

### Como Funciona

O sistema de revisão espaciada ajuda a reforçar memória e evitar esquecimento rápido. As perguntas são revisadas em intervalos crescentes:

- **1 dia depois**: Revisar material novo
- **3 dias depois**: Segunda revisão
- **1 semana depois**: Terceira revisão
- **2 semanas depois**: Quarta revisão
- **1 mês depois**: Revisão mensal

### Estrutura de Arquivos

As perguntas de revisão ficam em `learning/review-questions/`:

- `fundamentals.md` - Conceitos básicos de .NET
- `azure-services.md` - Serviços Azure
- `architecture.md` - Padrões arquiteturais
- `interview-questions.md` - Perguntas de entrevista

### Formato das Perguntas

Cada pergunta contém:
- Data de criação
- Data da última revisão
- Nível de confiança (1-5)
- Resposta atual
- Próxima revisão agendada

## 📊 Métricas e Tracking

### Tracking Semanal

Registrar no journal semanal:

- POCs/projetos em progresso

- Evolução de dificuldade dos challenges
- Novos conceitos aprendidos

- Próximos objetivos

## 🔄 Fluxo de Trabalho Semanal

### Segunda-feira - Planejamento
1. Revisar o **Backlog** no GitHub Project Board
2. Selecionar 3-5 tarefas para a semana
3. Mover tarefas selecionadas para **My Work**
4. Definir **Status** como `In progress`
5. Atribuir **Sprint** (ex: `Week 1`)

### Durante a Semana - Execução
1. Trabalhar nas tarefas de **My Work**
2. Atualizar progresso nas issues conforme necessário
3. Quando completar uma tarefa, mudar **Status** para `Done`
4. Tarefas concluídas aparecem automaticamente em **Done**

### Sexta/Sábado - Revisão e Planejamento
1. Revisar **Done** para visualizar progresso da semana
2. Decidir quais tarefas incompletas vão para a próxima semana
3. Atualizar **Sprint** para a próxima semana ou voltar para **Backlog**
4. Criar journal entry da semana
5. Planejar a próxima sprint
